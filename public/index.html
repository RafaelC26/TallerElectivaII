API Equipos y Jugadores

Cómo usar la API

Cree una cuenta, inicie sesión para recibir un token y envíelo en cada petición a equipos y jugadores.

¿Prefiere el navegador? Los mismos pasos se hacen desde Swagger UI con el botón Try it out.

  1. 1

    Registrarse

    Envíe nombre, email y una contraseña de al menos 8 caracteres con letras y números.

    POST /api/auth/registro 
    curl -X POST http://localhost:3000/api/auth/registro \
  -H "Content-Type: application/json" \
  -d '{"nombre":"Ana","email":"ana@example.com","password":"Clave2026"}'
  2. 2

    Iniciar sesión y copiar el token

    La respuesta incluye el campo token. Cópielo: vence según JWT_EXPIRES_IN (2 horas por defecto). El registro también devuelve uno.

    POST /api/auth/login 
    curl -X POST http://localhost:3000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"ana@example.com","password":"Clave2026"}'
  3. 3

    Enviar el token en cada petición

    En Swagger pulse Authorize y pegue solo el token (Swagger agrega Bearer). Desde otro cliente use el header Authorization: Bearer <token>.

    GET /api/equipos 
    TOKEN="pegue-aquí-su-token"
curl http://localhost:3000/api/equipos \
  -H "Authorization: Bearer $TOKEN"

Endpoints

Todas las rutas de /api/equipos y /api/jugadores exigen el header Authorization: Bearer <token>. PUT es una actualización parcial: solo cambian los campos enviados.

Equipos

GET /api/equipos Listar equipos. Filtros: nombre, ciudad, pagina, limite JWT
POST /api/equipos Crear un equipo JWT

Modelo de datos

Un equipo tiene muchos jugadores y cada jugador pertenece a un solo equipo. La relación se guarda en el lado de los muchos.

Equipo

colección equipos
  • _idObjectIdPK
  • nombreStringúnico
  • ciudadString
  • estadioString
  • anioFundacionNumber
  • entrenadorString
  • jugadoresJugador[]virtual
  • totalJugadoresNumbervirtual

Relación uno a muchos: un Equipo tiene de 0 a 25 Jugadores; cada Jugador pertenece a exactamente un Equipo.

Jugador

colección jugadores
  • _idObjectIdPK
  • nombreString
  • apellidoString
  • numeroCamisetaNumber1–99
  • posicionStringenum
  • fechaNacimientoDate15+ años
  • nacionalidadString
  • equipoObjectIdref Equipo

Jugador.equipo guarda el _id del equipo. Equipo no guarda un arreglo de jugadores: los obtiene con un populate virtual, así la relación nunca queda desincronizada. posicion admite Portero, Defensa, Centrocampista o Delantero.

Reglas de negocio

Cada regla se valida en el servidor y responde con un código HTTP y un mensaje claro en { error }.

  • Nombre de equipo único

    409 Conflict

    No puede haber dos equipos con el mismo nombre, sin importar mayúsculas: «Once Caldas» y «ONCE CALDAS» son el mismo.

  • El equipo debe existir

    422 Unprocessable

    Un jugador solo se crea o se transfiere a un equipo que exista en la base de datos.

  • Camiseta única en el equipo

    409 Conflict

    El número va del 1 al 99 y no se repite dentro de un mismo equipo. Fuera de ese rango responde 400.

  • Máximo 25 jugadores

    409 Conflict

    Un equipo con 25 jugadores no acepta más, ni por registro ni por transferencia, aunque lleguen peticiones al mismo tiempo (transacción).

  • Edad mínima de 15 años

    400 Bad Request

    La fecha de nacimiento debe corresponder a un jugador con al menos 15 años cumplidos.

  • Eliminación protegida

    409 Conflict

    Un equipo con jugadores no se elimina. Con ?cascada=true se eliminan el equipo y toda su plantilla.

  • Solo admin elimina

    403 Forbidden

    Los DELETE exigen rol admin; un usuario normal recibe 403. El admin se crea con npm run seed.

  • Registro sin privilegios

    201 Created

    El registro público siempre crea el rol usuario. Si alguien envía "rol": "admin", se ignora.

Seguridad

Qué protege a la API y a los datos de sus usuarios.

  • JWT HS256 con expiración

    Los tokens se firman con HS256 y vencen (2 horas por defecto). Un token vencido o alterado recibe 401.

  • Contraseñas con bcrypt

    Se guardan como hash bcrypt y nunca aparecen en las respuestas. El login no revela si un email existe.

  • Roles admin y usuario

    Cualquier usuario autenticado consulta, crea y edita; solo el rol admin puede eliminar.

  • Rate limiting en login

    Máximo 20 intentos de login o registro cada 15 minutos por IP, además de un límite general para /api.

  • Helmet: cabeceras seguras

    Content-Security-Policy, HSTS, X-Content-Type-Options y otras cabeceras que endurecen el navegador.

  • Protección contra inyección NoSQL

    Mongoose convierte operadores como {"$gt": ""} en valores literales antes de consultar.

  • Validación de datos

    Los esquemas validan tipos, rangos y formatos, y los ids se comprueban antes de tocar la base de datos.
